Step 03 // Hybrid PQC Defense Architecture
Why QUANTA Hybrid Handshakes Resist HNDL
QUANTA binds classical key exchange (X25519) with NIST FIPS 203 Post-Quantum KEM (ML-KEM-768). The resulting session key K = HKDF(K_classical ‖ K_pqc) remains computationally secure even if an adversary breaks the discrete log problem on X25519.
Classical Architecture (Vulnerable)
Key Exchange: X25519 (ECDH)
Session Key: K = HKDF(K_classical)
Authentication: ECDSA P-256
Symmetric Cipher: AES-256-GCM
Warning: Shor's algorithm on elliptic curves breaks K_classical → session key compromised.
QUANTA Hybrid Architecture (Post-Quantum Secure)
Dual KEM: X25519 (Classical) + ML-KEM-768 (Lattice)
Combiner: ss = K_classical ‖ K_pqc
Session Key: K = HKDF-SHA256(ss, "quanta-hybrid-v1")
Signature: ML-DSA-65 (NIST FIPS 204)
Symmetric Cipher: AES-256-GCM
Protected: Deriving K requires breaking both Module-LWE and ECDLP simultaneously.

Understanding Harvest-Now, Decrypt-Later (HNDL)
State-sponsored actors and adversaries currently record and store encrypted traffic on high-value networks. When quantum computing systems achieve sufficient fault-tolerant scale, Shor's algorithm will be run against recorded handshake transcripts to factor private keys and decrypt years of historical data retroactively.
QUANTA Mitigation: Incorporating ML-KEM-768 into the handshake ensures that deriving the master secret requires breaking lattice cryptography, which possesses no known quantum polynomial-time solution.
